# Контекст: auth

## Цель

- Авторизовать пользователя через OAuth2 Shikimori, чтобы получать access/refresh токены и разблокировать приватные API.
- Сохранять токены безопасно и отдавать статус авторизации в UI/DI без ручной обвязки в компонентах.

## Границы

- Сейчас покрыт только запуск OAuth-авторизации и запись токенов в secure storage.
- Не реализованы refresh-токен, выход из аккаунта, прокладка токена в сетевые клиенты и экраны профиля.
- UI ограничен технической кнопкой и текстовым индикатором статуса.

## Внешние интеграции

- `react-native-app-auth` для OAuth-дэнса с эндпойнтами Shikimori.
- `expo-secure-store` для хранения `accessToken` и `refreshToken`.
- Expo Constants для client id/secret и bundle identifier.
- DI-слой (`AuthModule`, контейнер экрана) подключает сервисы и ViewModel к React Navigation.

## Ожидания по качеству

- Токены должны храниться безопасно и очищаться при логауте.
- Статус авторизации должен корректно восстанавливаться при старте приложения.
- Ошибки OAuth должны обрабатываться в UI, не оставляя зависших состояний.
- Автообновление токена и отказоустойчивость сетевых вызовов нужно добавить в следующих итерациях.

## Текущее состояние

- Базовый клик по кнопке открывает OAuth и сохраняет токены, но проверка статуса синхронная и не ждёт SecureStore, из-за чего `isAuthorized` всегда truthy.
- Нет очистки токенов при `logout`, нет refresh-флоу, токены не подключены к Apollo/сетевым клиентам.
