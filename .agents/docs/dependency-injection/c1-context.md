# Контекст: dependency-injection

## Цель

- Отделить бизнес-логику фич от создания зависимостей и обеспечить предсказуемые области жизни сервисов.
- Дать единый композиционный корень для конфигурирования инфраструктуры (клиенты данных, темы, хранилища) и её переиспользования между экранами.

## Границы

- Охватывает мобильное приложение на React Native: корневой контейнер, фичевые модули и привязку к навигации.
- Не распространяется на сборочные скрипты и вспомогательные утилиты, где DI не задействован.

## Внешние интеграции

- Базируется на Inversify как механизме контейнеров и модулей.
- Подключён к React Navigation для наследования контейнеров между маршрутами и проброса параметров навигации.
- Используется в композиционном корне для конфигурации инфраструктурных сервисов и фичевых модулей.

## Ожидания по качеству

- Чёткие области жизни: singleton в контейнере и наследование от родительского контейнера, если локальной зависимости нет.
- Лёгкая заменяемость и тестируемость: модули можно перегружать или подменять при инициализации.
- Низкая связность фич: зависимости запрашиваются через контейнер, а не напрямую между модулями.
