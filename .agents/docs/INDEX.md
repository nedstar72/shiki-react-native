# Проектная документация

Этот файл служит входной точкой документации по проекту. В нём фиксируется, какой функционал уже реализован. При работе с документацией важно опираться на её структуру.

## Структура документации

- Каталоги тематик размещаются в `docs/<тема>/` и именуются в `kebab-case`.
- C4-структура ведётся отдельно для каждой тематики (фича, подсистема, домен).
- Внутри каталога тематики разбиты по C4-уровням:
  - `c1-context.md` — цели, границы и внешние связи.
  - `c2-containers.md` — приложения/сервисы, публичные API и интеграции.
  - `c3-components.md` — ключевые модули, данные и интерфейсы между ними.
  - `c4-code.md` — основные файлы, точки расширения и технические решения.

## Как читать

- Прочитать оглавление, чтобы увидеть доступные тематические разделы.
- Углубиться по необходимости: c1 → c2 → c3 → c4. Для быстрого понимания реализации достаточно c1 и заголовков c2; детали — в c3 и c4.
